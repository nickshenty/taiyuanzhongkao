## 📄 第一部分：长文档摘要（20分钟）

### 运行脚本

```bash
python3 01_长文档摘要.py
```

### 你会看到什么

脚本默认处理 `data/监管文件_普惠金融指导意见.txt`（一份约3000字的银保监会监管文件），演示：

1. **文档加载**：读取文件，统计长度
2. **智能分块**：将长文本按段落/句子边界分成多个小块（每块约1500字符，有重叠）
3. **逐块摘要**：AI对每块分别生成要点摘要
4. **汇总整合**：AI将各块摘要整合为一份完整的文档摘要
5. **保存结果**：自动保存为 `.md` 文件

### 核心知识点：分块摘要策略

为什么要分块？因为本地7B模型的上下文窗口有限（通常8K tokens≈4000字中文），长文档一次塞不进去。

```
长文档（3000字）
    ↓ 分块
[块1] [块2] [块3] [块4]
    ↓ 逐块摘要
[摘要1] [摘要2] [摘要3] [摘要4]
    ↓ 汇总整合
  最终摘要（500字）
```

**关键参数**：
- `CHUNK_SIZE = 1500`：每块字符数。太大→模型摘要质量下降；太小→丢失上下文
- `OVERLAP = 200`：块间重叠。确保块边界的信息不丢失
- 在句子/段落边界分块，比固定长度截断效果好得多

### 支持PDF文件

```bash
# 直接传入PDF文件路径
python3 01_长文档摘要.py /path/to/your_document.pdf
```

脚本会用 `pdftotext`（poppler工具包）提取PDF文字，然后走同样的分块摘要流程。

## 📋 第二部分：监管文件要点提炼（15分钟）

### 运行脚本

```bash
python3 02_监管文件要点提炼.py
```

### 你会看到什么

脚本对监管文件进行**深度结构化分析**，输出：

1. **文件核心定位**：这份文件是干什么的
2. **量化目标**：所有数字化指标（15%增长、0.3个百分点下降、首贷户20%等）
3. **重点政策举措**：5-8条核心政策
4. **时间节点**：所有涉及的时间要求
5. **基层工作要求**：银行需要落实的具体事项
6. **合规要点**：可能涉及违规风险的关键条款

还会生成一份**落地执行工作清单**，包含责任部门、时限和优先级。

### 核心知识点：Prompt工程——角色设定决定输出质量

```python
# 同一份文件，不同角色设定，输出完全不同

# 角色A：监管政策分析专家 → 偏向政策解读和合规要点
prompt = "你是银行监管政策分析专家。请提炼关键要点..."

# 角色B：普惠金融部门负责人 → 偏向落地执行和工作安排
prompt = "你是银行普惠金融部门负责人。请生成可执行的工作清单..."

# 角色C：风险管理部负责人 → 偏向风险识别和控制措施
prompt = "你是银行风险管理部负责人。请识别风险要点..."
```

**启示**：同一个AI模型，通过改变Prompt中的角色设定，可以产出完全不同视角的分析。实际工作中，你可以用不同角色"多跑几遍"，获得更全面的理解。

### 💡 动手试试

1. 把脚本中的角色改成"风险管理部负责人"，看输出有什么不同
2. 找一份你最近收到的监管文件，传入路径试试
3. 对比 `glm4:9b` 和 `deepseek-r1:7b` 的分析深度——推理型模型可能发现更隐含的合规要求

## 📊 第三部分：政策变化对照分析（20分钟）

### 运行脚本

```bash
python3 03_政策变化对照分析.py
```

### 你会看到什么

脚本对比 `政策文件_旧版.txt`（2025年版管理办法）和 `政策文件_新版.txt`（2026年修订版），自动识别：

1. **新增条款**：新版中新增的内容
2. **删除条款**：旧版中被删除的内容
3. **修改条款**：有实质性变化的条款（重点标注变化部分）
4. **关键变化解读**：3-5个最重要变化的详细解读
5. **执行建议**：基层银行需要做的调整
6. **制度衔接工作清单**：需要修订的制度、调整的参数、开展的培训

### 核心知识点：AI做对比分析的优势

人工对比两份文件，容易遗漏细节。AI的优势在于：
- **全文覆盖**：不漏掉任何一条变化
- **结构化输出**：新增/删除/修改分门别类
- **影响分析**：不只列出"改了什么"，还分析"意味着什么"

但也要注意：
- AI可能把格式变化误认为内容变化
- 数字变化（如200万→500万）AI能准确识别
- 语义变化（如"鼓励"→"要求"）AI也能捕捉到

### 💡 动手试试

1. 仔细看对照报告，检查AI有没有遗漏或误判的变化
2. 找你工作中的一份新旧制度文件，传入路径对比：
   ```bash
   python3 03_政策变化对照分析.py 旧版.txt 新版.txt
   ```
3. 把示例文件中的某些数字改一改，看AI能否发现

## 📚 第四部分：知识库问答检索（25分钟）

### 运行脚本

```bash
python3 04_知识库问答检索.py
```

### 你会看到什么

知识库包含4篇银行制度文件：
- 小微企业税收优惠政策
- 个人经营性贷款产品手册
- 普惠金融信贷风险管理制度
- 乡村振兴金融服务政策要点

脚本先演示5个示例问题，然后进入**交互模式**，你可以自由提问：

```
❓ 你的问题: 小微企业贷款额度最高是多少？
📖 检索到 2 篇相关文档:
   - 个人经营性贷款产品手册（匹配分: 12）
   - 小微企业税收优惠政策（匹配分: 5）
💡 回答: 根据个人经营性贷款产品手册，抵押经营贷最高1000万元...
```

### 核心知识点：简易检索 vs 语义检索

**本脚本的方案（关键词匹配）**：
```
用户问题 → 分词 → 关键词匹配文档 → 匹配分数排序 → 取TopK → AI回答
```
- 优点：简单、快速、无需额外依赖
- 缺点：只能匹配字面相同的词，"贷款利率"匹配不到"贷款定价"

**Open WebUI的方案（RAG语义检索）**：
```
文档 → 分块 → 向量化（embedding） → 存入向量数据库
用户问题 → 向量化 → 余弦相似度搜索 → 取TopK → AI回答
```
- 优点：语义级匹配，"贷款利率"能匹配到"资金定价"
- 缺点：需要下载embedding模型（约270MB）

### 🔧 进阶：用Open WebUI构建知识库

你Day3已经部署了Open WebUI（Docker端口3000），它内置了RAG功能：

1. **启动Docker Desktop** → 确认Open WebUI容器运行中
2. **打开浏览器** → `http://localhost:3000`
3. **进入工作区** → 左侧菜单 → 工作区 → 知识库
4. **创建知识库** → 点击"+" → 命名"普惠金融制度库"
5. **上传文档** → 把 `data/知识库/` 里的txt文件全部上传
6. **开始问答** → 新建对话 → 选择模型 → 附加知识库 → 提问

Open WebUI的RAG会自动做：
- 文档分块（自动）
- 向量化（用 `nomic-embed-text` 模型，需先下载）
- 语义检索（比关键词匹配智能得多）
- 引用标注（告诉你答案来自哪个文档的哪个部分）

如果首次使用提示需要embedding模型：
```bash
ollama pull nomic-embed-text
```
然后在Open WebUI设置 → 文档 → Embedding Model 中选择 `nomic-embed-text`。

## 📝 第五部分：会议纪要自动化（20分钟）

### 运行脚本

```bash
python3 05_会议纪要自动化.py
```

### 你会看到什么

脚本处理 `data/会议记录_普惠金融工作推进会.txt`（一份约2500字的分行会议记录），自动生成三份产出：

1. **结构化会议纪要**：会议信息、议程、内容摘要、决议、工作安排表
2. **待办事项清单**：提取所有有责任人的任务，标注时限和优先级
3. **一句话简报**：100字以内概括会议核心

### 核心知识点：会议纪要的完整自动化流程

```
┌──────────┐    ┌───────────┐    ┌──────────┐    ┌──────────┐
│ 录音文件  │ →  │ Whisper   │ →  │ 转写文本  │ →  │ AI整理   │ → 结构化纪要
│ (m4a/mp3) │    │ 转文字     │    │ (.txt)   │    │          │ → 待办清单
└──────────┘    └───────────┘    └──────────┘    └──────────┘  → 会议简报
```

本脚本实现的是最后一步（AI整理）。录音转文字部分需要额外工具。

### 🔧 录音转文字方案（选装）

**方案一：macOS系统自带（最简单）**
- macOS Sequoia 15.1+ 支持系统级录音转写
- 打开"语音备忘录"App → 录音 → 自动转写（需在设置中开启）

**方案二：Whisper命令行（免费、本地、推荐）**
```bash
# 安装（Apple Silicon优化版）
pip3 install mlx-whisper

# 使用（medium模型，平衡速度和质量）
python3 -c "
import mlx_whisper
result = mlx_whisper.transcribe('meeting.m4a', path_or_hf_repo='mlx-community/whisper-medium-3', language='zh')
print(result['text'])
" > meeting_transcript.txt
```

**方案三：WhisperUI（图形界面）**
- 下载：https://whisperui.com
- 支持Apple Silicon，拖拽音频文件即可转写
- 免费试用3天，之后需订阅

**完整工作流**：
1. 开会时录音（手机语音备忘录/录音笔）
2. 用Whisper转成文字（存为txt）
3. 运行 `python3 05_会议纪要自动化.py meeting_transcript.txt`
4. 得到结构化纪要 + 待办清单 + 简报

### 💡 动手试试

1. 检查AI生成的纪要，看有没有遗漏或错误
2. 修改脚本中的prompt，定制你单位喜欢的纪要模板
3. 如果安装了Whisper，试着录一段2分钟的语音，走完整流程
