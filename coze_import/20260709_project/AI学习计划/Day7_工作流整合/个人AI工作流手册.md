## 一、环境速查

### 1.1 日常启动流程

```bash
# ① 启动 Ollama（如未自动启动）
ollama serve

# ② 确认模型就绪
ollama list

# ③ 启动 Open WebUI（如Docker未自动运行）
docker start open-webui

# ④ 浏览器访问
open http://localhost:3000
```

### 1.2 Ollama 常用命令

| 命令 | 用途 |
|------|------|
| `ollama list` | 查看已安装模型 |
| `ollama run glm4:9b` | 启动对话（终端） |
| `ollama pull <模型名>` | 下载新模型 |
| `ollama rm <模型名>` | 删除模型 |
| `ollama ps` | 查看正在运行的模型 |
| `ollama stop <模型名>` | 停止模型运行 |
| `ollama show glm4:9b` | 查看模型详情 |

### 1.3 Docker 常用命令

| 命令 | 用途 |
|------|------|
| `docker start open-webui` | 启动 Open WebUI |
| `docker stop open-webui` | 停止 Open WebUI |
| `docker ps` | 查看运行中的容器 |
| `docker logs open-webui` | 查看日志（排查问题） |

### 1.4 Python 环境注意

> Day4发现：MacBook 上 python3 存在 xcrun 异常，依赖 Python 的脚本可能无法直接执行。

**修复方法**：
```bash
xcode-select --install
```

**变通方案**（如暂未修复）：
```bash
# 用纯 bash 调用 Ollama
ollama run glm4:9b "请帮我起草一份普惠金融业务通报..."
```

## 二、模型选用指南

### 2.1 已安装模型一览

| 模型 | 大小(Q4) | 流畅度 | 主力场景 |
|------|---------|--------|---------|
| **glm4:9b** | ~6GB | ★★★★★ | 公文写作、通报、报告 |
| **deepseek-r1:7b** | ~4.7GB | ★★★★★ | 逻辑推理、深度分析 |
| **qwen2.5:7b** | ~4.7GB | ★★★★★ | 数据摘要、快速分析 |
| gemma3:12b | ~7.9GB | ★★★★☆ | 综合任务、英文场景 |
| yi:9b | ~6GB | ★★★★☆ | 中文理解（备选） |
| phi3:14b | ~9GB | ★★★☆☆ | 轻量级长文本 |
| hunyuan:latest | ~6GB | ★★★★☆ | 腾讯系中文（备选） |

### 2.2 场景→模型速查

| 工作场景 | 首选模型 | 备选 | 理由 |
|---------|---------|------|------|
| 公文/通报/报告起草 | **glm4:9b** | qwen2.5:7b | Day4测试8.5分，格式标准，自动补落款 |
| 业务数据分析报告 | **deepseek-r1:7b** | qwen2.5:7b | 推理能力强，能发现数据趋势 |
| 监管文件要点提炼 | **qwen2.5:7b** | glm4:9b | 摘要全面，速度快 |
| 政策新旧版本对比 | **qwen2.5:7b** | glm4:9b | 对比细致，结构清晰 |
| 会议纪要整理 | **glm4:9b** | qwen2.5:7b | 格式规范，措辞正式 |
| 知识库问答 | **glm4:9b** | qwen2.5:7b | 中文理解好 |
| 邮件/短文润色 | **Apple Intelligence** | glm4:9b | 系统级一键完成 |
| 英文材料处理 | **gemma3:12b** | — | 英文能力最强 |
| 复杂逻辑推理 | **deepseek-r1:7b** | — | 推理型模型，深度分析 |

### 2.3 模型切换原则

- **日常用7B-9B**：流畅快速，满足90%场景
- **重要任务可切14B**：质量更高但速度稍慢
- **一次只跑一个模型**：16GB内存同时跑两个大模型会卡顿
- **用完即停**：`ollama stop <模型名>` 释放内存

## 六、常见问题排查

### Q1：Open WebUI打不开（localhost:3000无响应）

```bash
# 检查Docker是否运行
docker ps

# 如果没有open-webui容器，重新启动
docker start open-webui

# 如果容器不存在，重新创建
docker run -d -p 3000:8080 -v open-webui:/app/backend/data --restart always --name open-webui ghcr.io/open-webui/open-webui:main
```

### Q2：模型响应很慢

- 检查是否同时运行了多个模型：`ollama ps`
- 停止不用的模型：`ollama stop <模型名>`
- 确认没有其他大型程序占用内存
- 7B-9B模型在M5上应3-5秒内开始响应

### Q3：AI生成的内容有编造数据

- **不要直接使用AI生成的数字**，必须与实际数据核对
- 在Prompt中明确要求："只使用我提供的数据，不要编造任何数字"
- DeepSeek-R1在公文写作中有编造倾向，公文写作请用GLM4:9b
- 重要数字用 `[XX]` 占位符让AI填写结构，你手动替换

### Q4：Python脚本报 xcrun 错误

```bash
# 执行修复
xcode-select --install

# 修复后验证
python3 --version
```

### Q5：长文档处理结果不完整

- 检查文档是否超过模型上下文限制（~4000字中文）
- 使用Day6的分块摘要脚本：`python3 01_长文档摘要.py`
- 调整CHUNK_SIZE（默认1500字符）和OVERLAP（默认200字符）

### Q6：Open WebUI知识库问答不准确

- 确认已下载embedding模型：`ollama pull nomic-embed-text`
- 在Open WebUI设置 → 文档 → Embedding Model 中选择 `nomic-embed-text`
- 确认知识库中的文档已成功上传和处理
