# 高考志愿填报AI Agent — 架构设计

## 一、产品定位

**名称**：酉鸣升学AI顾问（暂定）  
**定位**：面向高考考生家长的智能志愿填报助手  
**核心价值**：基于大数据+行业洞察，提供个性化、可解释的志愿填报方案

### 2.2 核心模块设计

#### 模块1：对话管理器
- **意图识别**：判断用户问的是什么类型的问题
  - 院校查询（"XX大学怎么样"）
  - 专业解读（"计算机专业学什么"）
  - 政策咨询（"新高考怎么填报"）
  - 方案生成（"我考了XX分，能上什么学校"）
  - 比较分析（"XX大学和XX大学哪个好"）
  - 闲聊/其他

- **信息收集**（渐进式）：
  ```
  第1轮：省份 + 科类/选科 + 分数/位次
  第2轮：目标城市偏好（可选）
  第3轮：专业方向偏好（可选）
  第4轮：家庭背景/特殊需求（付费咨询阶段）
  ```

- **多轮对话记忆**：
  - 记住用户已提供的信息，不重复询问
  - 支持用户随时修改已提供的信息
  - 会话结束后保存用户档案（付费用户）

#### 模块2：决策引擎

- **院校匹配算法**：
  ```
  输入：省份、科类、分数/位次、城市偏好
  规则：
    1. 根据位次查找历年录取位次区间
    2. 冲（位次上浮10-15%）、稳（位次±5%）、保（位次下浮10-15%）
    3. 结合城市偏好筛选
    4. 标注录取概率（高/中/低）
  输出：候选院校列表（15-30所）
  ```

- **专业推荐逻辑**：
  ```
  输入：选科组合、兴趣方向、就业偏好
  规则：
    1. 选科匹配（物理/历史/化学等限制）
    2. 兴趣标签匹配
    3. 就业前景评分
    4. 院校优势专业加权
  输出：推荐专业列表（按匹配度排序）
  ```

- **方案生成器**：
  ```
  输入：候选院校 + 推荐专业 + 用户偏好
  规则：
    1. 生成冲稳保梯度方案（如：冲5个+稳5个+保5个）
    2. 每个志愿填报建议：院校+专业组合
    3. 风险评估（调剂风险、退档风险）
    4. 生成可解释的推荐理由
  输出：完整志愿方案 + 解释说明
  ```

#### 模块3：知识库（RAG架构）

- **向量数据库**：存储非结构化知识的向量表示
  - 院校介绍、专业解读、政策解读
  - 用于语义检索（"适合女生的专业" → 匹配相关专业）

- **结构化数据**：存储可精确查询的数据
  - 录取分数线、位次、招生计划
  - 用于精确匹配（"XX大学XX专业在XX省的录取位次"）

- **规则库**：存储填报规则和约束
  - 各省志愿填报规则（平行志愿/顺序志愿）
  - 选科要求
  - 体检限制
  - 加分政策

## 三、跨平台部署方案

### 3.1 Coze Bot（首选MVP）
- **优势**：开发快、内置知识库、支持发布到多渠道
- **实现**：
  1. 创建Coze Bot
  2. 上传知识库文档
  3. 设计Prompt模板（System Prompt）
  4. 配置插件（院校查询、分数线查询等）
  5. 发布为Bot，可嵌入网页/微信公众号

### 3.2 Deepseek接入
- **方式**：通过Deepseek API调用
- **实现**：
  1. 将知识库转换为Deepseek支持的格式
  2. 使用Deepseek的Function Calling能力
  3. 实现RAG检索逻辑
  4. 部署为API服务

### 3.3 豆包接入
- **方式**：通过火山引擎API调用
- **实现**：类似Deepseek，使用豆包的API + 知识库

### 3.4 统一后端方案（推荐）
```
                    ┌─────────────┐
                    │  统一API服务 │
                    │  (Flask/FastAPI) │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
         ┌────┴────┐ ┌────┴────┐ ┌────┴────┐
         │ Coze Bot│ │Deepseek │ │  豆包   │
         │  插件   │ │  API    │ │  API    │
         └─────────┘ └─────────┘ └─────────┘
```
- 构建统一的后端API服务
- 知识库和逻辑层统一管理
- 各平台通过API调用，实现"一次开发，多平台部署"

## 五、技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 知识库存储 | Coze知识库 + JSON文件 | 快速启动，后续迁移 |
| 向量数据库 | Coze内置 / Milvus | Coze够用，后期可迁 |
| LLM | Coze默认 / Deepseek / 豆包 | 多模型备选 |
| 后端框架 | FastAPI (Python) | 轻量、高效、易部署 |
| 前端 | 微信小程序 + H5 | 覆盖主流场景 |
