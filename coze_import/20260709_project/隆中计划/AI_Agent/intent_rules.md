# 酉鸣聊升学 - 意图识别规则

## 一、意图分类概览

| 意图ID | 意图名称 | 英文名 | 优先级 | 描述 |
|--------|---------|--------|--------|------|
| Intent 1 | 院校查询 | school_query | P1 | 查询院校信息、录取分数等 |
| Intent 2 | 专业解读 | major_analysis | P1 | 分析专业内容、就业方向等 |
| Intent 3 | 方案生成 | plan_generation | P1 | 生成志愿填报方案 |
| Intent 4 | 政策咨询 | policy_consultation | P1 | 解读高考政策、招生规则 |
| Intent 5 | 比较分析 | comparison | P2 | 对比院校/专业/城市等 |
| Intent 6 | 闲聊/问候 | chitchat | P3 | 问候、感谢等日常对话 |
| Intent 7 | 投诉/反馈 | feedback | P3 | 用户反馈问题或投诉 |
| Intent 8 | 兜底处理 | fallback | P4 | 无法识别的意图 |

## 二、意图识别规则

### Intent 1: 院校查询 (school_query)

**定义**：用户想了解特定院校的基本情况、录取分数、专业设置、就业情况等信息。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 院校名称 | 大学、学院、学校、学府 |
| 院校层次 | 985、211、双一流、重点大学、普通本科、公办、民办、独立学院 |
| 院校特征 | 省重点、部属高校、部省合建 |
| 查询动作 | 查一下、了解一下、想知道、怎么样、好吗、有多好 |

#### 触发示例

```
正面示例：
- "清华北大怎么样？"
- "帮我查一下复旦大学"
- "985大学有哪些？"
- "XX学校录取分数是多少？"
- "这个学校好不好？"
- "介绍一下XX大学"
- "XX大学在哪个城市？"

组合示例：
- "我是广东考生，能上什么985大学？"
- "帮我看看XX学校的计算机专业怎么样"
- "XX大学和XX大学哪个好考？"
```

#### 槽位提取

| 槽位名称 | 必需 | 说明 | 示例 |
|----------|------|------|------|
| school_name | ✅ | 院校名称 | 清华大学、北京大学 |
| province | ❌ | 省份 | 广东、北京 |
| year | ❌ | 年份 | 2024、2023 |
| subject | ❌ | 科类 | 物理类、历史类 |
| query_aspect | ❌ | 查询方面 | 录取分数、专业、就业 |

#### 处理逻辑

```
1. 提取院校名称
2. 判断是否有省份限定 → 检索对应省份录取数据
3. 判断查询方面：
   - 未指定 → 返回院校综合介绍
   - 指定录取分数 → 重点展示历年分数/位次
   - 指定专业 → 重点介绍该专业
   - 指定就业 → 重点展示就业数据
4. 结合用户科类/省份（如有）提供个性化信息
5. 输出回答
```

#### 回答规范

- 提供院校基本信息（层次、位置、背景）
- 提供录取数据（近三年分数/位次）
- 提供学科实力评价
- 提供报考建议
- 附上风险提示

### Intent 2: 专业解读 (major_analysis)

**定义**：用户想了解特定专业的学习内容、就业方向、发展前景、适合人群等信息。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 专业名称 | 专业、类、专业方向 |
| 学习内容 | 学什么、课程、学哪些、学出来、会什么 |
| 就业相关 | 就业、工作、前景、出路、毕业干什么、薪资、挣钱 |
| 发展相关 | 发展、发展前景、行业趋势、深造、考研、出国 |
| 分析动作 | 解读、分析、介绍、了解 |

#### 触发示例

```
正面示例：
- "计算机专业学什么？"
- "医学专业就业前景怎么样？"
- "帮我分析一下金融学"
- "会计学适合什么样的孩子？"
- "法学专业难不难？"
- "人工智能以后好就业吗？"

组合示例：
- "女孩子学什么专业好？"
- "物理类考生有哪些好专业？"
- "我孩子数学不好，能学计算机吗？"
- "计算机和电子信息哪个好？"
```

#### 槽位提取

| 槽位名称 | 必需 | 说明 | 示例 |
|----------|------|------|------|
| major_name | ✅ | 专业名称 | 计算机科学与技术、临床医学 |
| gender | ❌ | 性别倾向 | 男孩、女孩 |
| subject | ❌ | 科类 | 物理类、历史类 |
| concern | ❌ | 关注点 | 就业、考研、薪资、难度 |
| score_range | ❌ | 分数范围 | 600分以上、550分以下 |

#### 处理逻辑

```
1. 提取专业名称
2. 判断用户关注点：
   - 学什么 → 介绍核心课程
   - 就业 → 分析就业方向和行业
   - 前景 → 行业发展趋势
   - 适合谁 → 分析适合的性格/能力
3. 如有科类限定 → 筛选对应专业
4. 如有性别/性格倾向 → 做针对性建议
5. 输出回答
```

#### 回答规范

- 专业定义和学习内容
- 核心课程介绍
- 就业方向分析
- 行业发展前景
- 适合人群画像
- 报考注意事项（选科要求、身体限制等）

### Intent 3: 方案生成 (plan_generation)

**定义**：用户希望根据分数/位次生成一份志愿填报方案，包括冲稳保推荐。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 分数相关 | 分数、位次、省排名、能上、够得上 |
| 推荐动作 | 帮我选、推荐、推荐一下、给个方案 |
| 填报相关 | 志愿、怎么填、填报、报考、投档 |
| 目标相关 | 冲一冲、稳一稳、保一保 |

#### 触发示例

```
正面示例：
- "我考了600分，能上什么大学？"
- "帮我推荐一些学校"
- "文科生530分怎么填志愿？"
- "我的分数能上985吗？"
- "帮我做个志愿方案"
- "冲稳保怎么搭配？"

组合示例：
- "我是广东物理类考生，620分，想学计算机，能上什么学校？"
- "580分省排名15000，想留在省内，有什么推荐？"
- "我家孩子想学医，分数大概560，有哪些学校可选？"
```

#### 槽位提取

| 槽位名称 | 必需 | 说明 | 示例 |
|----------|------|------|------|
| province | ✅ | 省份 | 广东、山东 |
| subject | ✅ | 科类 | 物理类、历史类、文科、理科 |
| score | ❌ | 分数 | 600、580 |
| rank | ❌ | 位次 | 省排名12000 |
| major_preference | ❌ | 专业偏好 | 计算机、医学、经济学 |
| city_preference | ❌ | 城市偏好 | 省内、一线城市、南方 |
| plan_type | ❌ | 方案类型 | 冲稳保、保守型、激进型 |

#### 处理逻辑

```
1. 确认必要信息：
   - 省份 ✅
   - 科类 ✅
   - 分数/位次（至少有一个）
   
2. 如信息不完整 → 追问

3. 调用推荐算法：
   - 冲 (3-5所): 分数+5~20分，录取概率30%-50%
   - 稳 (5-8所): 分数±5分，录取概率50%-80%
   - 保 (3-5所): 分数-5~-20分，录取概率80%+

4. 如有专业偏好 → 结合专业筛选
5. 如有城市偏好 → 适当调整

6. 生成方案报告
```

#### 回答规范

- 明确说明推荐依据（分数、位次、往年数据）
- 分层展示：冲-稳-保
- 每所院校包含：
  - 院校名称
  - 预估录取概率
  - 推荐理由
  - 报考注意事项
- 整体填报策略建议
- 重要风险提示

### Intent 4: 政策咨询 (policy_consultation)

**定义**：用户想了解高考相关政策、招生规则、特殊类型招生等信息。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 新高考 | 新高考、3+1+2、3+3、选科、等级赋分 |
| 特殊招生 | 强基计划、强基、综合评价、综评、高校专项、地方专项、农村专项 |
| 志愿规则 | 平行志愿、顺序志愿、投档、专业级差、服从调剂 |
| 录取相关 | 录取规则、提档、调档、分数线、一分一段 |
| 加分政策 | 加分、少数民族、烈士子女 |

#### 触发示例

```
正面示例：
- "什么是强基计划？"
- "新高考怎么填志愿？"
- "平行志愿是什么意思？"
- "综合评价招生怎么报名？"
- "高校专项计划有什么要求？"
- "服从调剂是什么意思？"

组合示例：
- "我是农村考生，有什么优惠政策？"
- "报了强基还能报普通批次吗？"
- "分数刚好压线怎么填志愿？"
- "新高考选科有哪些注意事项？"
```

#### 槽位提取

| 槽位名称 | 必需 | 说明 | 示例 |
|----------|------|------|------|
| policy_type | ✅ | 政策类型 | 强基计划、平行志愿 |
| province | ❌ | 省份 | 广东（不同省份政策可能不同） |
| detail_aspect | ❌ | 关注细节 | 报名条件、流程、录取 |

#### 处理逻辑

```
1. 识别政策类型
2. 判断是否需要省份限定（新高考各省不同）
3. 确定用户关注的具体方面：
   - 是什么 → 政策定义
   - 怎么报 → 报名条件/流程
   - 怎么录 → 录取规则
   - 适合谁 → 人群分析
4. 检索最新政策数据
5. 输出回答
```

#### 回答规范

- 政策基本定义
- 报名条件
- 选拔/录取流程
- 时间节点
- 优劣势分析
- 适合人群判断
- 报考建议

### Intent 5: 比较分析 (comparison)

**定义**：用户想对两个或多个选项进行对比，以便做出选择。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 对比词 | 哪个好、区别、差别、不同、对比、和...比、比...好、选...还是... |
| 选择词 | 怎么选、选哪个、选哪个好、建议选、推荐选 |
| 犹豫词 | 纠结、犹豫、不知道选、好难选 |

#### 触发示例

```
正面示例：
- "计算机和电子信息哪个好？"
- "去大城市读普通大学还是小城市读重点大学？"
- "师范类和综合类大学怎么选？"
- "XX大学和XX大学哪个更好？"
- "文科生选法学还是汉语言文学？"

组合示例：
- "我孩子性格内向，学医好还是当老师好？"
- "计算机和医学怎么选？哪个更挣钱？"
- "是选省内211还是省外985？"
```

#### 槽位提取

| 槽位名称 | 必需 | 说明 | 示例 |
|----------|------|------|------|
| option_a | ✅ | 选项A | 计算机专业 |
| option_b | ✅ | 选项B | 电子信息专业 |
| compare_dimension | ❌ | 对比维度 | 就业、薪资、发展 |
| user_priority | ❌ | 用户优先级 | 更看重发展前景 |

#### 处理逻辑

```
1. 识别比较对象
2. 确定对比维度：
   - 院校对比：层次、学科、城市、就业
   - 专业对比：课程、就业、薪资、发展
   - 城市对比：发展机会、生活成本、气候
3. 收集双方优劣势数据
4. 客观列出对比结果
5. 如有用户优先级 → 根据优先级给出倾向性建议
6. 不替用户做决定，让用户自己权衡
```

#### 回答规范

- 先明确比较对象
- 多维度客观对比（用表格或列表）
- 列出各自优劣势
- 如用户有明确偏好 → 结合偏好分析
- 引导用户思考自己最看重的因素
- 不直接说"选A"或"选B"，而是"如果您更看重XX，建议选A"

### Intent 6: 闲聊/问候 (chitchat)

**定义**：用户的输入不涉及具体升学问题，而是日常问候、感谢等。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 问候 | 你好、您好、早上好、晚上好、嗨 |
| 感谢 | 谢谢、感谢、辛苦了、太好了 |
| 肯定 | 很好、不错、正解、说得对 |
| 结束 | 好的、知道了、就这样、再见 |
| 自我介绍 | 你是谁、你叫什么、你叫什么名字 |

#### 触发示例

```
正面示例：
- "你好"
- "谢谢你的帮助"
- "辛苦了"
- "再见"
- "你是AI吗？"
- "你是机器人吗？"

非触发示例：
- "你好，请问清华计算机多少分？" → 应识别为院校查询
```

#### 处理逻辑

```
1. 识别闲聊类型
2. 友好回应
3. 自然引导回正题
```

#### 回答规范

- 简洁友好
- 不啰嗦
- 适当引导回升学话题

---

### Intent 7: 投诉/反馈 (feedback)

**定义**：用户表达不满、提出建议或反馈问题。

#### 触发关键词

| 类别 | 关键词 |
|------|--------|
| 投诉 | 不好、不满意、垃圾、差、太差了 |
| 建议 | 希望、建议、改善、优化 |
| 错误反馈 | 错了、不对、不准确 |

#### 处理逻辑

```
1. 识别投诉类型
2. 表达歉意和理解
3. 如是信息错误 → 承认并承诺改进
4. 如是服务不满 → 表示歉意
5. 引导用户描述具体问题
6. 无法解决时 → 引导至人工客服
```

---

### Intent 8: 兜底处理 (fallback)

**定义**：无法识别用户意图，或用户输入无意义。

#### 触发条件

| 情况 | 示例 |
|------|------|
| 无意义输入 | "啊？""。...""？？？" |
| 无法识别 | 语义模糊、表达不清 |
| 超出范围 | 询问无关内容 |

#### 处理逻辑

```
1. 友好表示理解有困难
2. 尝试理解用户可能想问什么
3. 提供选项引导
4. 或请用户换一种方式表达
```

#### 回答模板

```
抱歉，我可能没有完全理解您的意思 😅

您是想了解：
1. 院校信息查询？
2. 专业解读分析？
3. 志愿填报方案？
4. 高考政策咨询？

请直接回复数字，或者换一种方式告诉我您的疑问，我会尽力帮您解答！
```

## 三、意图识别优先级规则

当一句话可能匹配多个意图时，按以下优先级处理：

```
Intent 1 (院校查询) > Intent 2 (专业解读) > Intent 3 (方案生成) > 
Intent 4 (政策咨询) > Intent 5 (比较分析) > Intent 6 (闲聊) > Intent 8 (兜底)
```

**示例**：
- "清华计算机多少分" → 优先识别为院校查询（Intent 1）
- "计算机和电子信息哪个分数高" → 优先识别为比较分析（Intent 5）


## 五、意图识别准确度提升技巧

### 1. 模糊匹配

```
用户："我想学IT"
系统识别：major_name = "计算机类"（IT = 信息技术 = 计算机类）
```

### 2. 别名识别

```
用户："中大"
系统识别：school_name = "中山大学"

用户："北大"
系统识别：school_name = "北京大学"

用户："人大"
系统识别：school_name = "中国人民大学"
```

### 3. 否定识别

```
用户："我不想学医"
系统识别：major_exclude = "医学类"
```

### 4. 程度词识别

```
"多少分能上" → 关注录取分数
"大概能上" → 关注院校层次
"一定上" → 需要谨慎，不承诺
```

## 六、意图识别失败处理

### 失败场景

| 场景 | 处理方式 |
|------|---------|
| 院校名称不确定 | 询问确认："您说的是XX大学吗？" |
| 专业名称模糊 | 列出可能选项："您是想了解计算机类、电子信息类还是其他专业？" |
| 分数单位不明 | 确认："您说的是高考成绩吗？满分是多少？" |
| 省份不明确 | 询问："请问您是哪个省份的考生？" |

### 追问话术

```
我需要确认一下：
- 您说的是 [重复用户关键词] 吗？
- 是 [选项A] 还是 [选项B]？

或者您可以更详细地描述一下您的疑问～
```
